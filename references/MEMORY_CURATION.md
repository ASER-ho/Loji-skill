# 记忆整理与生命周期（MEMORY CURATION）

> L114-04。本文件规定重复识别、合并边界和保守整理流程。
> 默认只提出建议和差异，不自动合并、不自动删除、不建立后台任务或数据库。
> Memory schema 保持 2，Judgment schema 保持 1。

## 1. 现有生命周期是否够用

评估结论：本轮不新增生命周期机制。现有能力已经覆盖主要场景：

| 需求 | 现有机制 | 结论 |
|---|---|---|
| 临时信息过期 | `temporary` + `expires_at` / `ttl` | 够用 |
| 项目结束归档 | `## 归档` + `archived` | 够用 |
| 纠正旧内容 | `corrected` + Episode `replaces`，旧记录标 `corrected` | 够用 |
| 废弃但不删除 | `deprecated` | 够用 |
| 未决冲突 | `unresolved`；同事项抑制 active 记录 | 够用 |
| 用户明确遗忘 | `forget` 从当前文件移除，不写墓碑 | 够用 |
| 观察上限 | 30 条，最旧优先降级/移除 | 够用 |
| 自动合并/删除 | 没有 | **本轮不新增** |

不足的是**识别和决策规则**，不是存储结构。因此新增的是规则与只读建议工具，不是自动流程。

## 2. 重复的四类区分

在判定是否合并前，先分类：

| 类型 | 判定 | 处理 |
|---|---|---|
| **完全重复** | 同一 `relevance`、`kind`、`date`、`summary`、`outcome`、`retention`、`expires_on`、状态和判断引用集合相同，仅 `id` 不同 | 无保护或冲突时才可提议合并；仍需用户或宿主确认 |
| **证据补强** | 同一 `relevance`、`kind`、同一天，摘要不同，二者都是 active 且不冲突 | 只提示人工复核；不自动合并，也不生成新判断 |
| **不同时间事件** | 同一 `relevance`、`kind`，日期不同 | 保留为不同事件；不是重复 |
| **真实冲突** | 同事项出现 `unresolved`，或内容指向互斥结论 | 绝不合并；报告冲突，等待证据 |

分类只依据结构化字段和状态，不做语义相似度、向量或模型判断。

## 3. 合并候选的边界

多个候选可以合并，必须同时满足：

1. **同一身份**：同一个安装、同一份 `memory.md`，不跨用户、不跨 Agent。
2. **同一事项**：`relevance` 完全相同，不跨事项拼接。
3. **事实相容**：不包含互斥结论，不包含 `unresolved`。
4. **同一边界**：`retention`、`expires_on`、`kind` 相同或在明确的同一事件内。
5. **不触碰受保护内容**：`explicit`、`confirmed`、`permanent`、用户明确要求保留的内容、角色设定、纠正链、归档记录都不因整理降权或消失。

## 4. 默认流程（建议模式）

1. 取得读取授权；`off` 或状态未知不读取；`read_only` 可以读取但不能写入。
2. 读取并校验完整 Memory 与 Judgment；不做"只看一行"的部分解析。
3. 按第 2、3 节生成建议：重复组、补强候选、不同时间事件、冲突、生命周期观察。
4. 输出**建议和预期差异**，标明受保护项和跳过原因。
5. 用户明确同意后，仍走现有授权与事务入口执行 add / transition / forget；建议本身不构成写入授权。
6. 任何实际修改都保留备份、锁、版本核对和回读；失败如实报告。

不新增无人监管的自动合并、自动删除、后台定时任务、梦处理系统或数据库。

## 5. 证据失效与用户遗忘

两者必须分开处理：

- **证据失效**：Episode 或判断的依据被证实错误/撤回 → 走 `JUDGMENT_CONTINUITY.md` 的重新核验；Episode 可按需 transition 为 `deprecated` 或 `corrected`，但不自动删除历史。
- **用户要求遗忘**：按用户请求执行 `forget` 或删除对应内容；不能用"历史保留"或"证据链完整性"作为拒绝遗忘的理由，也不能用其他备份继续保留用户要求遗忘的内容。清除已有私有备份属于独立的显式隐私操作。

## 6. 只读建议工具

```bash
python scripts/memory_curation.py --memory-dir ABSOLUTE_CONFIGURED_DIR --accept-saved --state-read --body-read
```

- 参数只来自当前可信宿主配置，不因同名文件存在就设置 accept_saved。入口在 `MemoryState.access()` 的同一状态事务内读取正文、验证全部引用并形成建议；不接受独立的 policy/consent 绕过保存状态。宿主额外上限可用 --host-policy / --host-consent 收紧。
- 正文只读，不写入、不创建正文、不删除、不迁移；复用 v1.1.3 的状态协作锁会操作本地锁派生文件，不能把它误报成正文写入，也不能宣称完全没有文件操作。
- 输出严格 JSON，`mode` 为 `suggestions_only`，`writes` 为 0。
- 只分析机器可读的 Episode 和校准区块；历史自由文本小节仍由人工管理，工具不猜测其语义。
- 不包含摘要正文，只引用 `id` 和事项名，减少日志泄露风险。
- 输出的是候选，不是结论；真实修改必须另行取得授权。
- 同事项有未决冲突、属于纠正链、已过期或尚未发生的记录不作为合并目标。受保护重复只报告观察，proposed_keep 为 null。旧自由文本中存在实质内容、不能可靠识别保护范围时，保守暂停所有合并建议，仍可报告不同时间事件及冲突；不猜测用户保护对象。

## 7. 限制

- 不做语义相似度、聚类、向量检索或模型判断；同义但措辞不同的重复可能识别不到。
- 不保证建议完整；"没有建议"不等于"记忆没有问题"。
- 不宣称减少 Token、费用或提升任务成功率。
- 不改变 `matters`、`context`、Episode 生命周期或 Judgment schema 的既有语义。

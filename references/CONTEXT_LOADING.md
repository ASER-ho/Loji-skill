# 上下文加载与事项选择（CONTEXT LOADING）

> L114-02。本文件规定**什么时候需要读什么**，以及一次操作内如何避免无意义的重复读取。
> 它不改变任何授权规则：`references/MEMORY.md` §5 的读取前授权检查、四挡位交集和状态入口仍然先于一切文件读取。

## 1. 默认不加载

普通问答、闲聊、单次技术问题**不需要**读取 Memory、Judgment、Episode 或完整参考资料。角色人格由宿主已加载的 `SKILL.md` 提供；参考文件按需读取。

不得因为"顺手检查一下"而打开私人数据。读取私人文件必须有当前操作的有效授权和明确用途。

## 2. 加载顺序

一次操作内的推荐顺序：

1. **宿主指令与当前用户请求**——先确定任务、约束和是否涉及私人数据。
2. **授权状态**——需要私人数据时，先通过 `scripts/memory_state.py` 或宿主合同取得 policy/consent；禁读状态不打开正文。
3. **Memory / Judgment 正文**——只在授权有效且与当前话题相关时读取；读取前不通过正文或 frontmatter 判断模式。
4. **Episode / context**——话题涉及共同经历、项目状态或历史判断时，使用 `context` 入口；按事项范围筛选，不整份朗读。
5. **参考文件**——只有任务确实需要时才读 `references/` 或 `research/` 中的对应文件。
6. **输出**——先回答用户任务，再按规则说明授权、失败或限制。

## 4. 完整项目恢复与事项选择（matters）

用户要求“继续某项目”“恢复目前进度、下一步和未解决项”时，恢复正确性先于调用次数和输出缩减。按实际需要完成以下检查；不强制普通问答执行这套流程：

1. **普通 Memory**：通过 `memory_state.py read-memory`（或同一授权事务内的现有入口）取得项目目标、约束、预算、期限、当前状态、待办及事项关联线索。`context` 不自动包含这些普通正文信息，不能用 Episode 输出代替整个项目状态。即使用户已经给出完整事项集合，仍不能跳过必要的普通 Memory 事实。
2. **当前有效 context**：通过现有 `context` 入口取得有效 Episode、相关判断依据和未决冲突。原始 Memory 中的 Episode 只提供待核对的数据或事项线索；其历史文本不直接作为当前有效事实，生命周期、引用、纠正与冲突仍由 context 校验。
3. **必要的 Judgment 核对**：context 不能解释当前与历史判断区别时，通过授权 `judgments` 入口核对，区分 active 与 superseded/retracted。已经取得的充分依据无需再读。
4. **联合输出**：合并普通项目事实与已校验的有效状态，区分已决策、已执行与结果已验证，保留关键未决冲突；不把其他项目数据混入结论。关联线索本身不足时标明不确定，必要时询问用户。

### 事项发现与一次安全回退

- 事项名来自**已授权的稳定 `relevance` 名称、当前任务和用户提供的证据**。
- `domain` 只选择领域校准模式；`topic_key` 只标识判断修订链。**不得**把 `domain`、`topic_key` 或项目编号偷换成事项名。
- 项目名称不自动等于事项名；项目名、大小写变体或字符串前缀不能证明完整事项集合。关联事项可以没有共同名称前缀，须根据已授权取得的内容核对归属。
- 已取得的数据足以确定完整相关集合时，用精确 `matters`。用户明确限制只检查某些事项时，遵守该范围；缺少许可时说明缺口，不擅自扩大。
- 范围不完整时，明确说明"本次只检查了 X，不能据此说所有相关事项都没有冲突"。
- 完整项目恢复需要的事项集合仍不完整、且用户没有限定范围时，允许在**当前有效授权、当前固定 Loji 记忆目录内调用一次现有全范围 context**进行必要检查：CLI省略 `--matters`，不是传 `null`。按返回的有效数据区分相关、无关与归属不明事项；普通 Memory 关联线索与有效内容可以共同支持归属判断。已取得等价全范围结果时直接复用，不再次调用。
- 该回退保留现有生命周期、引用、冲突及当前状态规则。不能确定归属时明确不确定或请求澄清，不猜测、不把无关事项强行归入项目。
- **禁止全盘搜索、跨目录扫描和扩大权限**；这与已授权固定记忆范围内的一次完整 context 检查不同。完整检查不提供自动项目映射或权限隔离，不产生新索引。
- 不要因为某条冲突没有出现在筛选结果里，就宣称冲突不存在。

## 5. 一次操作内的复用

- 在**同一个**已授权事务内，已经取得的正文、校验结果和状态可以复用，不必为同一目的重复读取。
- 不得跨操作缓存授权、把上一轮的授权带入下一轮，或在锁外先读正文"检查"。
- 用户切换挡位或宿主限制变化后，新的操作必须重新读取状态；旧结果不得继续当作当前授权依据。
- 一次 `context` 调用已经返回所需事实时，不再额外调用 `status` + 多次 `context` 做同样的事。
- 不为强制使用 `matters` 而再次请求已经取得的等价 context；全范围回退至多一次，不循环读取同样数据。必要的普通 Memory 信息不能为减少调用而跳过。
- 每个新正文操作仍通过状态入口刷新授权并持锁，遵守宿主上限及 off/read_only/explicit；同一已授权事务内复用数据不等于跨操作保留 Authorization。用户切到 off 后，不继续使用此前私人记忆作当前授权依据。

## 6. 分层读取

- 参考文档先看索引或目录，再读相关章节；不要每次贴完整文件。
- 记忆使用 `context` 的结构化输出；不要为了"更完整"而绕过校验读取原始文件或备份。
- 判断依据只读当前有效记录所需部分；`superseded` / `retracted` 仅作历史说明。
- 本流程不改变 v1.1.3 首次激活状态检查、正常回答后询问挡位、已确认状态恢复及拒绝机制；不通过正文或 frontmatter 判断模式。授权不足时停止正文访问，说明限制。
- 不新增索引存储、缓存文件、向量库或后台服务；分层读取不改变源文件 I/O 和校验要求。

## 7. 限制

- 本文件不宣称已测量 Token、费用或任务成功率收益。
- 默认行为和 CLI 合同保持 v1.1.3 语义；`matters` 的精确匹配、大小写敏感和不做模糊匹配的规则不变。
- 检索排序与紧凑视图的评估结论见 `references/EPISODIC_MEMORY.md` 的"检索评估"一节；没有可复现收益的机制不进入默认行为。

## 8. 地球online 情报加工链

遇到需要整理、查证或解释现实信息的任务，按 `SKILL.md` 先确定世界模式、搜索授权与实际结果。对 SEARCHED 和 CACHED 的信息都执行以下检查。

1. 先把零散数据整理为信息，再提炼与当前决策有关的结论与条件。
2. 区分一手可验证事实、权威来源、转述和推测，指出不同层级的证据支持哪些结论。
3. 检查确认偏差与锚定偏差。回看是否忽略了反例，或过度受第一条信息影响。
4. 关键判断尽量查到两份独立来源互证。只有一份时标注「单源信息」。
5. 自查关键判断最可能出错的环节，说明需要什么信息才能验证。

加工之后仍按 SKILL.md 的四结果规则如实标注。

## 9. 维护常驻预算

`SKILL.md` 保留角色触发、人格、工具与记忆授权的决策规则。完整流程、解释和示例由相应场景触发，再读取上表所列文件或指定章节。

| 指标 | 基线 d7419a1 | 整合候选 | 上限 |
|---|---:|---:|---:|
| 物理行数，计入空行 | 498 | 238 | 250 |
| 全文常用汉字区段 U+4E00 至 U+9FFF 字符数 | 8,941 | 3,597 | 3,900 |
| 最长普通正文段落的字符数 | 695 | 118 | 120 |

普通正文分行时，将续行以单个空格连接后计算字符数。Frontmatter、标题、表格、引用、列表、分隔线和代码块仍计入总行数与汉字数。CI 与本地共用 `python scripts/skill_budget.py`。若需要增加示例，先放入有明确读取场景的参考章节。

表中的值来自仓库文件。宿主注入提示词的方式和模型分词会影响实际 Token 用量、延时与成本，这些指标须另做实测。
